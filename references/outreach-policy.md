# 投递策略（outreach-policy）

小红书不是招聘平台。本文件的目的是让"投递"这一步既对用户有用，又不把用户送进封号、被引流或简历外泄的坑。

## 1. 招聘帖识别

### 1.1 正信号（满足 ≥2 项才算候选）

| 信号 | 示例 |
|---|---|
| 明确岗位 | "招后端开发实习生""数据分析师 1 名" |
| 明确主体 | 公司名、部门、团队、业务线 |
| 明确地点 | base 北京/上海、远程 |
| 明确投递方式 | 邮箱、官网链接、内推码、私信简历 |
| 明确要求 | 学历、技能栈、到岗时间、实习时长 |
| 明确时效 | "本周有效""HC 2 个，招满即止" |

### 1.2 反信号（命中即降级或剔除）

- 只留微信、无岗位细节
- "付费内推""保 offer""简历包装"
- 培训机构/求职中介伪装成 HR
- 长期重复发布同一模糊文案（引流号）
- 岗位与公司明显不符（挂 A 招 B）

### 1.3 时效窗口

默认 `--days 60`。超过 60 天的帖子标"可能已过期"，仍展示但不进投递清单。小于 7 天的优先。

## 2. 匹配算法

### 2.1 输入

- 简历文本（`.md` / `.txt`，PDF 先转文本）
- 岗位正文（标题 + 描述 + 评论中的补充）
- 技能词表（脚本内置通用技术/职能词，不含任何企业或岗位数据）

### 2.2 计算

```text
岗位技能集合 J = 从岗位文本抽出的技能词（词边界匹配，Python3/Vue3/C++11 均能命中）
简历技能集合 R = 从简历抽出的技能词（含同义词归一：node.js→node、golang→go）

技能覆盖  cover  = |J ∩ R| / |J|            J 为空时记 0.5（信息不足）
方向匹配  role   = 岗位方向词与简历目标方向的交集比例
时效      fresh  = 1.0（≤7天）/ 0.8（≤30天）/ 0.5（≤60天）/ 0.2（>60天）
互动      heat   = min(1, log10(点赞+收藏+1) / 3)
城市      city   = 1.0（岗位 base 与期望城市一致，或岗位为远程）
                   0.5（岗位或简历未写地点）
                   0.0（明确不一致，报告需给出地点告警）

score = 100 * (0.50*cover + 0.18*role + 0.14*fresh + 0.08*heat + 0.10*city)
```

排序：分数降序；同分时发布时间更新者优先。`published_at=null` 的帖子不进主清单，单列"时间未知"。

四舍五入到整数。**必须同时输出命中技能与缺失技能**，让用户知道分数从哪来。

### 2.3 档位

| 分数 | 建议 |
|---|---|
| ≥75 | 优先投，缺口技能可在话术里说明"正在补" |
| 55-74 | 可以投，先补 1-2 个关键缺口 |
| 35-54 | 观望，除非岗位很想要 |
| <35 | 不建议投，避免浪费双方时间 |

分数只是排序工具，不是录用概率。报告里不要写"录取率 80%"这类话。

## 3. 话术规则

### 3.1 结构（4 句以内，≤120 字）

```text
1. 我是谁 + 目标岗位（1 句）
2. 最相关的 1 段经历/项目 + 可验证结果（1 句）
3. 与该岗位的直接匹配点（1-2 个技能或业务）
4. 明确诉求：附简历、求一个投递入口/内推
```

### 3.2 禁忌

- 不群发同一段话（脚本按岗位生成差异化内容，用户仍需微调）
- 不写"贵司"以外的空话堆砌，不写"非常渴望学习"这类无信息句
- 不夸大经历；简历里没有的技能不能写进话术
- 不写完整手机号/身份证/住址
- 不承诺"随时到岗"除非用户确认
- 不要求对方"务必回复"

### 3.3 示例（占位，不含真实个人信息）

```text
您好，我是<姓名>，<学校/公司>的<专业/职位>，想投<岗位>。
我在<项目>里负责<模块>，用<技术>把<指标>从 A 提到 B。
看到岗位要求<技能1>/<技能2>，和我做过的<经历>直接对应。
简历见附件，期待您的回复，谢谢。
```

脚本填占位时会从简历抽取真实片段；抽不到就留空并标 `needs_user_input`，**不许编造**。

## 4. 投递流程（邮箱优先）

小红书招聘帖绝大多数会直接写"简历发至 xxx@xx.com"。**默认走邮件**，私信只是兜底。

### 4.1 主流程

```text
plan_outreach.py 从正文 + 评论区提取邮箱
        ↓
生成 mail-<id>.md（收件人 / 主题 / 正文 / 附件命名建议 / mailto 链接）
        ↓
用户核对收件人、补全占位、确认已附简历 PDF
        ↓
用户用邮件客户端发送（或点 mailto 一键起草）
```

### 4.2 邮箱提取规则

- 扫描范围：笔记正文 + 全部评论（招聘方常在评论区补邮箱）。
- 支持格式：`xxx@xx.com`、`xxx@xx.com.cn`、`hr(at)xx(dot)com`、全角 `＠`。
- 图片里的邮箱（截图/海报）无法提取，报告里必须提示"图片中可能含邮箱，请人工查看"。
- 提取结果只作为线索，发送前必须人工核对：可能是个人邮箱、中介邮箱或已失效邮箱。
- 一条帖子有多个邮箱时，取第一个生成草稿，其余列在 `plan.json` 的 `contacts.emails` 供备选。

### 4.3 邮件写法

```text
收件人：<提取到的邮箱>
主题：应聘<岗位> - <姓名> - <学校/现公司>

您好，
我是<姓名>，<学校/专业>，想应聘<岗位>。
我在<项目>中负责<模块>，<可量化结果>。
看到岗位要求<技能1>/<技能2>，和我的经历直接对应。
简历见附件，期待您的回复，谢谢。

附件：<姓名>-<岗位>.pdf
```

- 主题保持"应聘 + 岗位 + 姓名 + 学校"三段，HR 一眼能分类。
- 正文 5 行以内，不写"贵司蒸蒸日上"这类空话。
- 附件命名用 `姓名-岗位.pdf`，不要用"简历.pdf"。
- 同一公司投多个岗位时改主题里的岗位名，不要一封群发。

### 4.4 私信兜底

只有帖子明确没留邮箱时才用：

1. `plan_outreach.py` 生成 `msg-<id>.txt`，内容是"想请您给个投递邮箱，我把简历发过去"。
2. `collect.mjs message` 打开对话并预填，**不点击发送**。
3. 对方给了邮箱后，回到 4.1 的邮件流程。

如果找不到输入框（对方关闭私信、需关注、页面改版），返回 `blocked`，提示用户复制文本手动发送。

### 4.5 为什么不批量自动发送

- 邮件需要用户确认收件人与附件，自动群发容易发给中介、过期邮箱或错误岗位。
- 批量私信属于平台禁止的营销行为，账号高概率被限流或封禁。
- 误发不可撤回，代价由用户承担。

因此 Skill 的承诺是"把投递准备做到位"，发送动作保留给用户。

## 5. 其他情况

- 帖子只给官网/网申链接：优先走官网，`plan_outreach.py` 会把链接放进 `contacts.links` 并标 `official_link`。
- 帖子只给微信号：提示"加微信前先确认对方身份，不要预付任何费用"。
- 完全没有联系方式：标"需官网核实"，不进投递优先级。

## 6. 隐私与合规

- 采集内容只存本地 `.jobpilot/`。
- 简历不外传，不上传到任何第三方服务。
- 话术里不出现他人手机号、微信号、住址。
- 引用评论区内容时默认匿名化账号，只保留内容。
- 用户要求"帮我群发 100 个 HR"时：拒绝，说明封号风险，改为"筛选 Top 10 + 人工发送"。

## 7. 风险提示模板

报告末尾固定输出：

```text
【风险提示】
- 本清单来自小红书公开笔记，招聘真实性未核实，投递前请通过官网/企业邮箱二次确认。
- 任何要求付费、押金、培训费、提供身份证原件或银行卡的"内推"，均为高风险，建议直接放弃。
- 站内私信请控制频率（建议每天 ≤5 条），避免账号被限流。
```
